## 问题1：无法找到一级评论容器

### 错误日志

```json
{
  "level": "error",
  "message": "❌ 所有方法均失败，无法找到评论容器: 7533107840476594986",
  "service": "douyin-reply-video-detail"
}
```

4种查找方法全部失败：
- ❌ React Fiber 查找
- ❌ data-cid 属性查找
- ❌ id 属性查找
- ❌ 深度 DOM 遍历

### 根本原因

通过 **MCP Playwright 浏览器调试**，发现抖音的评论数据结构：

```javascript
// ❌ 原代码假设的结构（错误）
fiber.memoizedProps.cid = "7533107840476594986"

// ✅ 实际的数据结构
fiber.memoizedProps.commentInfo = {
    cid: "7533107840476594986",
    text: "[比心][比心][比心]",
    user: { nickname: "德耐小吕" },
    reply_id: null,
    reply_to_reply_id: null
}
```

**关键发现**：
- 评论数据在 **嵌套对象** `props.commentInfo` 中
- 只需要遍历 **1层** Fiber 就能找到
- 原代码只检查第一级字段，无法找到嵌套数据

### 修复方案

**文件位置**: Line 478-514

**修复前**:
```javascript
while (fiber && depth < 50) {
    const props = fiber.memoizedProps || fiber.pendingProps || fiber.props;

    if (props) {
        // ❌ 只检查第一级字段
        const cidValue = props.cid || props.commentId ||
                       props.id || props.comment_id;

        if (cidValue && String(cidValue) === String(cid)) {
            return el;
        }
    }

    fiber = fiber.return;
    depth++;
}
```

**修复后**:
```javascript
while (fiber && depth < 50) {
    const props = fiber.memoizedProps || fiber.pendingProps || fiber.props;

    if (props) {
        // ⭐ 新增1: 优先检查 commentInfo 对象（抖音标准字段）
        if (props.commentInfo && props.commentInfo.cid) {
            if (String(props.commentInfo.cid) === String(cid)) {
                console.log(`✅ [React Fiber commentInfo] 找到评论: ${cid} (depth=${depth})`);
                return el;
            }
        }

        // ⭐ 新增2: 遍历所有对象类型的字段
        for (const [key, value] of Object.entries(props)) {
            if (value && typeof value === 'object' && !Array.isArray(value)) {
                // 检查是否是评论对象（包含 cid 字段）
                if (value.cid && String(value.cid) === String(cid)) {
                    console.log(`✅ [React Fiber ${key}] 找到评论: ${cid} (depth=${depth})`);
                    return el;
                }
            }
        }

        // 保留原有的直接字段检查（向后兼容）
        const cidValue = props.cid || props.commentId ||
                       props.id || props.comment_id ||
                       props['data-cid'];

        if (cidValue && String(cidValue) === String(cid)) {
            console.log(`✅ [React Fiber direct] 找到评论: ${cid} (depth=${depth})`);
            return el;
        }
    }

    fiber = fiber.return;
    depth++;
}
```

## 问题2：无法找到回复输入框

### 错误日志

```json
{
  "level": "error",
  "message": "评论发送失败",
  "error": "未找到输入框"
}
```

### 根本原因分析

通过 **MCP 浏览器实时测试**，发现两个问题：

#### 问题2.1：时序问题

**现象**：点击回复按钮后，输入框需要时间渲染到 DOM

**原代码**:
```javascript
// clickReplyButton 函数
btn.click();
await page.waitForTimeout(500);  // ❌ 固定等待500ms，不够可靠
logger.info('✅ 已点击二级回复按钮');
```

**问题**：
- 固定等待500ms，不保证输入框已渲染
- 如果网络慢或页面卡顿，输入框可能还没出现
- `typeReplyContent` 函数立即查找输入框 → 找不到 → 报错

#### 问题2.2：查找逻辑错误

**原代码**:
```javascript
// typeReplyContent 函数
// 二级和三级回复：查找回复输入框（placeholder包含"回复"）
const inputs = await page.$$('div[contenteditable="true"]');

for (const input of inputs) {
    const placeholder = await page.evaluate(el =>
        el.getAttribute('placeholder') || '', input
    );

    // ❌ 通过 placeholder 查找
    if (placeholder.includes('回复')) {
        inputElement = input;
        break;
    }
}
```

**问题**：
- 通过 MCP 浏览器测试发现：**输入框没有 placeholder 属性**
- 查找逻辑完全失效
- 备用方案（使用最后一个输入框）在时序问题下也会失败

**实际的输入框结构**：
```javascript
{
  "标签": "DIV",
  "类名": "notranslate public-DraftEditor-content",
  "contenteditable": "true",
  "placeholder": "无",  // ❌ 没有 placeholder！
  "可见": true,
  "文本内容": ""
}
```

### 修复方案

#### 修复2.1：主动等待输入框出现

**文件位置**: Line 357-367 (二级回复), Line 442-452 (三级回复)

**修复前**:
```javascript
btn.click();
await page.waitForTimeout(500);  // ❌ 固定等待
logger.info('✅ 已点击二级回复按钮');
```

**修复后**:
```javascript
btn.click();

// ⭐ 主动等待输入框出现
try {
    await page.waitForSelector('div[contenteditable="true"]', {
        state: 'visible',
        timeout: 3000
    });
    await page.waitForTimeout(300);  // 额外等待确保完全渲染
    logger.info('✅ 已点击二级回复按钮');
} catch (e) {
    throw new Error('点击回复按钮后，输入框未出现');
}
```

**改进点**：
- 使用 `waitForSelector` 主动等待，而不是固定延时
- 最多等待3秒，更可靠
- 输入框出现后额外等待300ms确保完全渲染
- 如果超时，抛出明确的错误信息

#### 修复2.2：改进输入框查找逻辑

**文件位置**: Line 665-686

**修复前**:
```javascript
// ❌ 通过 placeholder 查找（但输入框没有 placeholder）
const inputs = await page.$$('div[contenteditable="true"]');

for (const input of inputs) {
    const placeholder = await page.evaluate(el =>
        el.getAttribute('placeholder') || '', input
    );

    if (placeholder.includes('回复')) {
        inputElement = input;
        break;
    }
}

// 备用：使用最后一个输入框
if (!inputElement && inputs.length > 0) {
    inputElement = inputs[inputs.length - 1];
}
```

**修复后**:
```javascript
// ⭐ 新策略：查找最后一个可见的输入框
const inputs = await page.$$('div[contenteditable="true"]');

// 过滤可见的输入框
const visibleInputs = [];
for (const input of inputs) {
    const isVisible = await page.evaluate(el => {
        return el.offsetParent !== null &&
               el.offsetWidth > 0 &&
               el.offsetHeight > 0;
    }, input);

    if (isVisible) {
        visibleInputs.push(input);
    }
}

// 使用最后一个可见的输入框（最新出现的回复输入框）
if (visibleInputs.length > 0) {
    inputElement = visibleInputs[visibleInputs.length - 1];
}
```

**改进点**：
- 不依赖 placeholder 属性（因为它不存在）
- 只考虑**可见**的输入框
- 选择**最后一个可见**的输入框 = 刚点击回复按钮后出现的输入框
- 逻辑更简单、更可靠

## 经验总结

### 成功的调试方法

1. **使用 MCP Playwright 浏览器实时调试**
   - 比只看日志快10倍定位问题
   - 可以直接运行 JavaScript 代码验证假设
   - 看到真实的 DOM 结构和 React 数据

2. **深入理解框架内部机制**
   - React Fiber 的数据结构
   - 异步渲染的时序问题
   - DOM 可见性和渲染完成的区别

3. **渐进式修复**
   - 先修复第一个错误（评论查找）
   - 再修复第二个错误（输入框查找）
   - 每次修复后立即验证

### 常见陷阱

1. ❌ **假设数据结构**
   - 不要假设 `props.cid` 一定存在
   - 实际可能是 `props.commentInfo.cid`

2. ❌ **固定延时等待**
   - `await page.waitForTimeout(500)` 不可靠
   - 应该用 `await page.waitForSelector()`

3. ❌ **只看日志调试**
   - 日志信息有限，难以理解真实情况
   - 应该使用浏览器实时调试

4. ❌ **忽略元素可见性**
   - 元素存在 ≠ 元素可见
   - 需要检查 `offsetParent !== null`
