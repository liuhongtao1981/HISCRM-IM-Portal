# 短信验证码调试指南

**文档类型**: 🔧 调试指南
**创建时间**: 2025-12-02
**适用场景**: 短信验证码流程未按预期工作

---

## 📋 问题诊断

### 症状：没有发送 SMS 验证请求就关闭了 tab

根据代码逻辑，可能有以下几种原因：

#### 原因 1：用户在第一个确认对话框选择了"否"

**流程**:
1. Worker 检测到需要验证
2. IM 端弹出对话框："检测到需要验证，是否继续？"
3. 用户点击"否 - 取消操作"
4. Worker 收到 'no' 响应，直接关闭 tab

**日志特征**:
```
[douyin-platform] 收到用户选择: no
[douyin-platform] ⚠️ 用户选择取消验证
[douyin-platform] 📋 用户选择详情: userChoice=no, accountId=xxx
[douyin-platform] 准备关闭标签页...
[douyin-platform] ✅ 标签页已关闭
```

**解决方案**: 这是正常行为，用户主动取消了验证。

---

#### 原因 2：验证类型不是短信验证

**流程**:
1. Worker 检测到验证弹窗（可能是二维码验证）
2. IM 端弹出对话框，用户点击"是"
3. `handleSMSVerification` 开始执行
4. 找不到"发送验证码"按钮（因为是二维码验证）
5. 返回失败，但 tab 不会关闭

**日志特征**:
```
[douyin-platform] 用户选择继续验证，准备处理短信验证码...
[douyin-platform] 📱 开始处理短信验证码流程...
[douyin-platform] 📋 当前页面状态检测: {
  hasVerificationText: true,
  hasSMSButton: false,  // ❌ 关键：没有短信按钮
  buttonCount: 3,
  allButtons: ['二维码验证', '取消', '关闭']
}
[douyin-platform] ❌ 未找到发送验证码按钮！
[douyin-platform] 💡 可能原因：
   1. 验证类型不是短信验证（可能是二维码验证）
   2. 页面元素还未加载完成
   3. 按钮文本不匹配
[douyin-platform] 💡 已发现的按钮文本: ['二维码验证', '取消', '关闭']
[douyin-platform] ❌ 短信验证失败！
[douyin-platform] 💡 失败原因: 未找到发送验证码按钮，可能不是短信验证
[douyin-platform] 验证失败，保留标签页以便用户手动操作
```

**解决方案**:
1. 检查日志中的 `allButtons` 字段，查看实际的按钮文本
2. 如果是二维码验证，需要用户手动扫码
3. 考虑添加二维码验证的自动处理

---

#### 原因 3：页面元素还未加载完成

**流程**:
1. 验证弹窗刚出现
2. `handleSMSVerification` 立即执行
3. 此时"发送验证码"按钮尚未渲染完成
4. 找不到按钮，返回失败

**日志特征**:
```
[douyin-platform] 📋 当前页面状态检测: {
  hasVerificationText: true,
  hasSMSButton: false,  // ❌ 按钮尚未加载
  buttonCount: 0,       // ❌ 没有任何按钮
  allButtons: []
}
[douyin-platform] ❌ 未找到发送验证码按钮！
```

**解决方案**: 在 `handleSMSVerification` 开始前添加等待时间：

```javascript
// 在 platform.js 中，调用 handleSMSVerification 之前
await page.waitForTimeout(2000); // 等待页面元素加载
const verifyResult = await handleSMSVerification(page, requestSMSCodeCallback);
```

---

#### 原因 4：按钮文本不匹配

**流程**:
1. 验证弹窗正常显示
2. 但"发送验证码"按钮的文本与预期不符（如"发送"、"获取"等）
3. 查找逻辑匹配失败

**日志特征**:
```
[douyin-platform] 📋 当前页面状态检测: {
  hasVerificationText: true,
  hasSMSButton: false,
  buttonCount: 3,
  allButtons: ['发送', '取消', '关闭']  // ❌ 只有"发送"，没有"发送验证码"
}
```

**解决方案**: 扩展按钮匹配逻辑：

```javascript
// 在 send-reply-to-comment-video-detail.js 中
const sendSMSButton = await page.evaluate(() => {
    const buttons = Array.from(document.querySelectorAll('button, div[role="button"], span'));
    for (const btn of buttons) {
        const text = btn.textContent?.trim() || '';
        // 扩展匹配条件
        if (text.includes('获取验证码') ||
            text.includes('发送验证码') ||
            text === '发送' ||
            text === '获取' ||
            text.includes('verification code')) {
            return btn;
        }
    }
    return null;
});
```

## 🛠️ 快速修复建议

### 修复 1：添加页面加载等待

在 `platform.js` 的 `handleSMSVerification` 调用前添加等待：

```javascript
// 用户选择继续验证
logger.info('用户选择继续验证，准备处理短信验证码...');

// ✅ 添加等待，确保页面元素加载完成
await page.waitForTimeout(2000);

const verifyResult = await handleSMSVerification(page, requestSMSCodeCallback);
```

### 修复 2：扩展按钮匹配逻辑

在 `send-reply-to-comment-video-detail.js` 中扩展按钮文本匹配：

```javascript
const sendSMSButton = await page.evaluate(() => {
    const buttons = Array.from(document.querySelectorAll('button, div[role="button"], span'));

        const text = btn.textContent?.trim() || '';

            text.includes('发送验证码') ||
            text === '发送' ||
            text === '获取' ||
            text.includes('验证码')) {  // ✅ 新增泛匹配

        }
    }

```

### 修复 3：检测验证类型

在 `detectVerification` 中更准确地识别验证类型：

```javascript
// 在 send-reply-to-comment-video-detail.js 的 detectVerification 函数中
const verificationInfo = await page.evaluate(() => {
    const bodyText = document.body.textContent || '';

    // 检测短信验证
    const hasSMSVerification =
        bodyText.includes('短信验证码') ||
        bodyText.includes('接收短信验证码') ||
        bodyText.includes('发送验证码');

    // 检测二维码验证
    const hasQRVerification =
        bodyText.includes('扫码验证') ||
        bodyText.includes('扫描二维码') ||
        bodyText.includes('抖音APP扫描');

    // ✅ 如果两种都检测到，优先判断为二维码验证（更常见）
    if (hasQRVerification && hasSMSVerification) {
        return { detected: true, type: 'qrcode', ... };
    }

    if (hasSMSVerification) {
        return { detected: true, type: 'sms', ... };
    }

    if (hasQRVerification) {
        return { detected: true, type: 'qrcode', ... };
    }

    return { detected: false };
});
```

## ✅ 调试检查清单

使用以下检查清单诊断问题：

- [ ] Worker 日志中是否有 `收到用户选择:` 日志？
  - 如果是 `no`，说明用户取消了验证
  - 如果是 `yes`，继续检查下一步

- [ ] 日志中是否有 `📋 当前页面状态检测:` 输出？
  - 检查 `hasSMSButton` 是否为 `true`
  - 检查 `allButtons` 中是否包含验证码相关按钮

- [ ] 日志中是否有 `❌ 未找到发送验证码按钮` 错误？
  - 查看 `allButtons` 的实际内容
  - 确认是否为二维码验证

- [ ] 日志中是否有 `✅ 标签页已关闭` 输出？
  - 确认是哪个分支关闭的 tab
  - 检查是否为用户取消导致

- [ ] IM 客户端是否弹出了对话框？
  - 如果没有弹出，检查 WebSocket 连接
  - 检查 Master 是否正常转发事件
