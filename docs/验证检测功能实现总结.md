## 功能概述

实现了抖音评论发布时的安全验证检测机制，当平台触发验证（短信验证码/扫码验证）时：
1. ✅ Worker 端自动检测验证弹窗
2. ✅ 提取验证信息（类型、手机号、消息）
3. ✅ 通过 Master 转发给 IM 端
4. ✅ 等待用户选择（继续验证 / 取消任务）
5. ✅ 根据用户选择执行相应操作

## Socket.IO 消息流

### 完整消息链路

```
Worker 检测到验证弹窗
  ↓
[Worker] emit: worker:verification:request
  ↓ (Master 转发)
[Master] emit: verification:request → IM 端
  ↓
IM 端显示弹窗，用户选择
  ↓
[IM 端] emit: client:verification:response
  ↓ (Master 转发)
[Master] emit: worker:verification:response:{request_id} → Worker
  ↓
Worker 收到用户选择，执行操作
```

### 消息格式

#### 1. `worker:verification:request` (Worker → Master)

```json
{
  "request_id": "verify_acc-xxx_1701511234567",
  "account_id": "acc-xxx",
  "verification_type": "sms",
  "message": "为确保是本人操作抖音账号，请输入当前手机号198******35收到的短信验证码",
  "phone_number": "198******35",
  "has_sms_button": true,
  "has_qrcode_option": true,
  "context": {
    "aweme_id": "7533083869034138931",
    "comment_level": 1,
    "reply_content": "你好呀..."
  },
  "timestamp": 1701511234567
}
```

#### 2. `verification:request` (Master → IM 端)

```json
{
  "request_id": "verify_acc-xxx_1701511234567",
  "account_id": "acc-xxx",
  "verification_type": "sms",
  "message": "为确保是本人操作抖音账号，请输入当前手机号198******35收到的短信验证码",
  "phone_number": "198******35",
  "has_sms_button": true,
  "has_qrcode_option": true,
  "context": { ... },
  "timestamp": 1701511234567
}
```

#### 3. `client:verification:response` (IM 端 → Master)

```json
{
  "request_id": "verify_acc-xxx_1701511234567",
  "choice": "yes",  // or "no"
  "timestamp": 1701511234567
}
```

#### 4. `worker:verification:response:{request_id}` (Master → Worker)

```json
{
  "choice": "yes",  // or "no"
  "timestamp": 1701511234567
}
```

## 返回状态定义

### verification_pending

**含义**: 用户选择继续验证，等待短信验证码验证

**返回数据**:
```json
{
  "success": false,
  "status": "verification_pending",
  "reason": "等待短信验证码验证",
  "data": {
    "aweme_id": "7533083869034138931",
    "verification_type": "sms",
    "phone_number": "198******35",
    ...
  }
}
```

**后续操作**: TODO - 实现短信验证码处理

---

### verification_cancelled

**含义**: 用户选择取消验证，任务已终止

**返回数据**:
```json
{
  "success": false,
  "status": "verification_cancelled",
  "reason": "用户取消验证",
  "data": {
    "aweme_id": "7533083869034138931",
    "verification_type": "sms",
    ...
  }
}
```

**后续操作**: 标签页已关闭，任务结束

---

### verification_error

**含义**: 验证请求处理失败（超时、Socket 断开等）

**返回数据**:
```json
{
  "success": false,
  "status": "verification_error",
  "reason": "验证请求失败: Verification request timeout (5 minutes)",
  "data": {
    "error_message": "Verification request timeout (5 minutes)",
    ...
  }
}
```

**后续操作**: 重试任务或放弃

## 性能与安全考虑

### 性能

- **超时机制**: 5 分钟后自动超时，避免长时间占用资源
- **消息大小**: 验证消息 < 1KB，不会造成网络负担
- **并发处理**: 每个账户独立处理验证请求，互不干扰

### 安全

- **手机号脱敏**: 只显示脱敏后的手机号（`198******35`）
- **request_id 唯一性**: 使用 `verify_{accountId}_{timestamp}` 格式，避免冲突
- **超时保护**: 防止验证请求无限期等待

## 相关问题排查

### 问题 1: IM 端未收到验证请求

**可能原因**:
1. IM 端未连接到 Master 的 `/client` 命名空间
2. Master 端未正确转发消息
3. Socket.IO 连接断开

**排查步骤**:
1. 检查 IM 端 Socket.IO 连接状态
2. 查看 Master 日志，确认是否接收到 Worker 验证请求
3. 查看 Master 日志，确认是否转发到 Client 命名空间
4. 使用浏览器开发者工具检查 WebSocket 连接

---

### 问题 2: Worker 端未收到用户选择

**可能原因**:
1. IM 端未正确发送 `client:verification:response`
2. Master 端未正确转发响应
3. `request_id` 不匹配

**排查步骤**:
1. 检查 IM 端控制台，确认是否发送响应
2. 查看 Master 日志，确认是否接收到 IM 端响应
3. 比对 `request_id` 是否一致
4. 查看 Worker 日志，确认是否监听正确的事件

---

### 问题 3: 验证检测失败

**可能原因**:
1. 验证弹窗文本内容变化
2. 等待时间不足（1.5 秒）
3. DOM 结构变化

**排查步骤**:
1. 使用 MCP 浏览器查看实际弹窗文本
2. 调整 `detectVerification()` 中的关键字匹配
3. 增加等待时间（`page.waitForTimeout(2000)`）
4. 查看日志中的检测结果
